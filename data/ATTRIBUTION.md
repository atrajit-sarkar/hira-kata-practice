## How entries were selected

Rules follow `docs/SPEC.md` §4 and §15.1. Since version 2 the bank covers the **whole dictionary**,
not only its common entries. In short:

1. **Reading:** the first kana reading not tagged `ok`, `sk`, `ik` or `rk`, preferring a *common*
   one when the entry has several; it must be pure hiragana or pure katakana (ー counts as katakana).
   Each word has `common: true` when its entry has any common kana or kanji element (JMdict's
   news1/ichi1/spec1/gai1 priority markers) — the core vocabulary of version 1.
2. **Spelling filters:** no ゐゑヰヱゎヮヵヶゕゖぢづヂヅをヲゝゞヽヾ・＝; no ー, ゔ or small ぁぃぅぇぉ in
   hiragana; must not start with ー, a small kana, っ/ッ or ん/ン, nor end with っ/ッ; 2–9 characters
   (single characters only for JLPT N5/N4 words); こんにちは and こんばんは are excluded because
   their particle は is read "wa", which the displayed romaji cannot express.
3. **Senses:** only senses that apply to the chosen reading; senses tagged archaic, obsolete, vulgar,
   X-rated, sensitive, derogatory, rare or dated are dropped; at most 3 senses × 4 English glosses.
4. **Function words:** entries whose first sense is only a particle, auxiliary, conjunction, copula,
   prefix, suffix, counter or unclassified are skipped.
5. **Additional quality filters** (added after reviewing random samples of the bank):
   - entries whose main sense is sexual/adult content are skipped, and such senses are removed
     from other entries (e.g. the anatomical sense of あそこ);
   - senses that only name a trademark (JMdict field `tradem`) are removed, which drops entries such
     as brand names of medicines;
   - the `kanji` list only contains written forms with at least one kanji, so forms such as
     Ｔシャツ, ＯＫ or １つ are not shown as "kanji"; forms with characters outside the Unicode BMP
     (rare extension kanji without font coverage, e.g. 𠮟) are dropped too.
   - added after reviewing random samples of the *non-common* entries, and applied to non-common
     entries only (common words are unaffected): senses that only name something — JMdict misc
     name types such as person, company, organization, product, work, fictional character, deity,
     place, service or event — are removed, which drops entries like フーディン (a Pokémon) or
     ビートルズ (a band) while keeping ordinary senses of the same entry; Ryukyuan-language senses
     (dialect `rkb`) are removed because they are not standard Japanese;
   - the adult-content list was extended with explicit terms found in the full dictionary.
6. **Part of speech:** `posCategory` comes from the first kept sense. Nouns that can take の
   (`adj-no`) and prenominal nouns (`adj-f`) count as nouns; all other `adj-*` codes are adjectives.
7. Homophones (same kana, different entries) are all kept.
8. **Script-ambiguous romaji:** a question only shows the romaji, so no romaji may belong to both a
   hiragana and a katakana word. This is checked over the whole bank. When exactly one of the two
   scripts has common words for that romaji, the other script's (non-common) words are dropped —
   so the obscure hiragana homophone ないふ (内府) cannot remove ナイフ “knife”. Otherwise (both
   sides common, e.g. *mizu* みず “water” / ミズ “Ms”, or neither side common) every word of that
   romaji is dropped.

Build of 2026-11-14 (JMdict 3.6.2+20261109214828): 219,040 entries in, **168,267 words** out
(135,556 hiragana, 32,711 katakana; **21,671 common**), 7.84 MB gzip (53.6 MB uncompressed).
Skipped: 16,518 mixed-script and 871 other-script readings, 16,087 too long, 5,845 without a usable
sense, 4,554 with excluded characters, 3,323 proper-name or Ryukyuan-only entries, 1,562
script-ambiguous romaji (rule 8), 811 function words/affixes, 583 adult-content entries, 459 too
short, 87 ending in a sokuon, 48 with a bad first character, 21 non-standard hiragana, 2 without a
usable reading, 2 blocklisted. The common words are the version 1 bank minus three explicit terms.
The `meta.counts` object in `words.json.gz` always holds the exact figures of the current file.

## Rebuilding

```sh
npm run build:words                 # uses cached downloads in .cache/wordbank/ when present
npm run build:words -- --refresh    # download fresh copies of JMdict and the JLPT lists
npm run build:words -- --samples=100   # print more random sample words at the end
npm run build:words -- --uncommon-samples=100   # ... and more random non-common words
```

The build writes one word per line before compressing, removes the version 1 `data/words.json`,
and refuses to write a file above the 25 MB budget.

The script asks the GitHub API for the latest `jmdict-eng-*.json.tgz` release asset (~11.5 MB); if the
API is unreachable it uses the newest cached archive, or else the pinned 3.6.2+20261109214828 release. Downloads are
parsed as data only (gzip/tar, JSON, CSV) and never executed. If the JLPT lists cannot be loaded,
every word gets `jlpt: null` and `meta.jlptSource` is `null`. After rebuilding, run
`node --disable-warning=ExperimentalWarning --test test/wordbank.test.js`.
